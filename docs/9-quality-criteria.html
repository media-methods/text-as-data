9 Quality criteria & validation

Note🎯 Learning goals

After working through Tutorial 9, you’ll be able to…

  • Explain what quality criteria are and why we need them for text-as-data methods
  • Explain why we should validate automated analyses
  • Validate a dictionary against manual coding with precision, recall, and F1

1 Quality criteria

In Tutorial 8, we classified TV series as crime series with our own dictionary: About one in five series was a crime series. But can we trust this number - for example, if we wanted to report it in a paper or use it as a variable in further analyses?

To answer this question, we need quality criteria. For text-as-data methods, four criteria are often discussed:

Criterion Question Example
Validity Do we measure what we want to measure? Does our dictionary really find crime series?
Robustness Do we get similar results with the same data, but other methods? Do we find the same share of crime series with another, similar dictionary?
Reproducibility Do we get the same results with the same data and methods? Does a fellow student re-running our code on our data get the same results?
Replicability Do we get similar results with the same methods, but other data? Does our dictionary work as well for series from another time period?

Robustness, reproducibility, and replicability are necessary, but not sufficient: A result can be robust, reproducible, and replicable - and still not measure what we want to measure. This is why we focus on validity today.

Automated content analyses can produce results within seconds. But this does not mean that the results are correct: Errors can arise during preprocessing (e.g., stemming), operationalization (e.g., which features we include in a dictionary), or analysis (e.g., which threshold we use). This is why Grimmer and Stewart (2013, p. 271) recommend:

“Validate, Validate, Validate. […] What should be avoided, then, is the blind use of any method without a validation step.”

Validation helps us understand where our automated analysis goes wrong - and how wrong it is.

2 Validation via manual coding

2.1 The gold standard

There are many ways to validate automated analyses (for an overview, see Birkenmaier et al., 2024). Here, we focus on the most common one: the comparison with manual coding.

The logic is simple: We code the same texts a) automatically and b) manually. Then, we compare both codings. The manual coding is often called the “gold standard”, since we assume that human coders can capture the “true” value of a variable in a text.

WarningIs manual coding really a “gold standard”?

Not necessarily! Human coders also make mistakes and often disagree with each other. Song et al. (2020) show that the quality of the manual coding strongly affects the quality of the validation. They recommend that the gold standard…

  • is based on a random sample of texts,
  • is coded by at least two coders with sufficient intercoder reliability (e.g., Krippendorff’s \(\alpha \geq .7\)),
  • is large enough (in their simulation, more than 1,300 texts, i.e., more than 1% of all texts).

In this tutorial, we only code 20 series - for practical reasons. Keep in mind that results based on such small samples are very uncertain.

2.2 The confusion matrix

To compare automated and manual coding, we use a confusion matrix. For our crime dictionary, it looks like this:

The confusion matrix
Manual: crime Manual: non-crime
Dictionary: crime True positive (TP) False positive (FP)
Dictionary: non-crime False negative (FN) True negative (TN)
  • True positive: a crime series is correctly classified as “crime”
  • True negative: a non-crime series is correctly classified as “non-crime”
  • False positive: a non-crime series is wrongly classified as “crime”
  • False negative: a crime series is wrongly classified as “non-crime”

2.3 Precision, recall, and F1

Based on the confusion matrix, we calculate three common metrics:

Precision tells us whether all texts we classify as “crime” really are crime series, i.e., whether our analysis produces few false positives:

\[Precision = \frac{TP}{TP + FP}\]

Recall tells us whether we find all crime series, i.e., whether our analysis produces few false negatives:

\[Recall = \frac{TP}{TP + FN}\]

F1 is the harmonic mean of both. It is useful if we need one metric that combines precision and recall:

\[F_1 = 2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}\]

All three metrics range from 0 (bad) to 1 (perfect).

Importantly, precision and recall cannot be optimized independently: Improving one often worsens the other. Remember the thresholds from Tutorial 8? With a threshold of at least one crime feature, we find more crime series (recall ↑) - but also more wrong ones (precision ↓). With a threshold of at least two features, we find fewer wrong ones (precision ↑) - but miss many crime series (recall ↓).

WarningWhich values are “good enough”?

There are no fixed rules (yet). As a rough guideline, you can orient yourself to common thresholds for intercoder reliability: Values of about .8 or higher suggest that an automated analysis produces valid results.

But which metric matters most depends on your research question: If you want to find all crime series (e.g., to analyze them in detail), recall is more important. If you want to make sure that the series you analyze really are crime series, precision is more important.

3 Validation in R

Validating a dictionary in R involves four steps:

  1. Draw a random sample of texts
  2. Code the sample manually (the “gold standard”)
  3. Merge manual & automated codings
  4. Compare both: precision, recall & F1

For the last step, we need the package caret. Make sure that you install it first (you only need to do this once):

# install.packages("caret")

# load packages (every time you restart R)
library(tidyverse)
library(quanteda)
library(caret)

First, we repeat our dictionary analysis from Tutorial 8. Since we classify series based on the number of crime features, we do not need dfm_weight(). The variable automated contains our automated classification: 1 = crime series (at least one crime feature), 0 = non-crime series.

# read in the data
data <- read.csv2("data/data_tvseries.csv", encoding = "UTF-8")

# preprocessing (as in Tutorial 8)
tokens_tv <- data |>
  corpus(text_field = "Description") |>
  tokens(remove_punct = TRUE,
         remove_numbers = TRUE,
         remove_symbols = TRUE) |>
  tokens_tolower()

# our crime dictionary (as in Tutorial 8)
dict_crime <- dictionary(list(
  crime = c("crim*", "police*", "gun*", "shot*", "dead*",
            "murder*", "kill*", "court*", "suspect*",
            "witness*", "arrest*", "officer*", "verdict*")))

# apply the dictionary & classify
crime_tv <- tokens_tv |>
  dfm() |>
  dfm_lookup(dictionary = dict_crime) |>
  convert(to = "data.frame") |>
  bind_cols(data) |>
  mutate(automated = if_else(crime > 0, 1, 0))

3.1 Step 1: Draw a random sample

We draw a random sample of 20 series with slice_sample(). With set.seed(), we make sure that we all get the same 20 series (see Tutorial 5 for set.seed()).

We keep only the variables we need for coding: the ID of each document (doc_id), its title, and its description. We also add an empty variable manual for our manual coding. Importantly, we do not include the automated classification - so that it cannot influence our manual coding.

set.seed(42)

sample <- crime_tv |>
  slice_sample(n = 20) |>
  select(doc_id, Title, Description) |>
  mutate(manual = NA)

Then, we save the sample as a .csv file with write.csv2():

write.csv2(sample, "data/validation_sample.csv", row.names = FALSE)

3.2 Step 2: Code the sample manually

Now we leave R. Open validation_sample.csv (e.g., in Excel), read each description, and fill in the column manual:

  • 1 if the description shows that the series is a crime series
  • 0 if the description shows that the series is not a crime series

As in any manual content analysis, you should follow a clear codebook with coding instructions. Save the file as validation_sample_coded.csv in your data folder - in the same format (separated by semicolons).

Then, we read in our coding with read.csv2():

sample_coded <- read.csv2("data/validation_sample_coded.csv")

3.3 Step 3: Merge both codings

Next, we add the automated classification to our manual coding. We use left_join() and match both data sets via doc_id.

caret needs both classifications as factors with the same levels. We therefore convert both variables with factor():

validation <- sample_coded |>
  select(doc_id, manual) |>
  left_join(crime_tv |> select(doc_id, automated),
            by = "doc_id") |>
  mutate(manual = factor(manual, levels = c(0, 1)),
         automated = factor(automated, levels = c(0, 1)))

3.4 Step 4: Compare both codings

Finally, we compare both codings with confusionMatrix() from the caret package. We need to specify…

  • data: the automated coding
  • reference: the manual coding (our gold standard)
  • mode = "prec_recall": that we want precision, recall, and F1
  • positive = "1": which value indicates that a series is a crime series
cm <- confusionMatrix(data = validation$automated,
                      reference = validation$manual,
                      mode = "prec_recall",
                      positive = "1")

# confusion matrix
cm$table
          Reference
Prediction  0  1
         0 15  1
         1  0  4
# precision, recall & F1 (rounded)
round(cm$byClass[c("Precision", "Recall", "F1")], 2)
Precision    Recall        F1 
     1.00      0.80      0.89

Let’s start with the confusion matrix at the top. It shows how many series were classified as 0 or 1 by the dictionary (“Prediction”) and in our manual coding (“Reference”):

  • 4 series are crime series according to both codings (true positives)
  • 15 series are non-crime series according to both codings (true negatives)
  • 0 series were wrongly classified as crime series by the dictionary (false positives)
  • 1 series was wrongly classified as non-crime series by the dictionary (false negative)

What does this mean for our metrics?

  • Precision = 1.00: All 4 series classified as crime series really are crime series.
  • Recall = 0.80: We find 4 of the 5 crime series - we miss one.
  • F1 = 0.89: Overall, the dictionary seems to work well.

But careful: With only 20 series (and only 5 crime series!), these values are very uncertain. A single different coding decision would change them considerably.

💡 Take-Aways

  • quality criteria: criteria to ensure the quality of research, e.g., validity, robustness, reproducibility, and replicability
  • validity: Do we measure what we want to measure?
  • validation via manual coding: comparing automated and manual coding (“gold standard”) of a random sample: set.seed(), slice_sample(), write.csv2(), left_join()
  • confusion matrix: true/false positives and true/false negatives
  • precision: Are all texts we classify as X really X? recall: Do we find all texts that are X? F1: harmonic mean of both: confusionMatrix()

🤓 Smart Hacks

TipSmart Hack 1: Calculating precision and recall by hand

confusionMatrix() is convenient, but you can also calculate the metrics yourself with summarise() and mutate(). This helps to understand what the metrics mean:

validation |>
  summarise(TP = sum(automated == 1 & manual == 1),
            FP = sum(automated == 1 & manual == 0),
            FN = sum(automated == 0 & manual == 1)) |>
  mutate(precision = TP / (TP + FP),
         recall = TP / (TP + FN),
         f1 = 2 * precision * recall / (precision + recall))
  TP FP FN precision recall        f1
1  4  0  1         1    0.8 0.8888889

round = (n, places) => {

  const d = 10 ** places;
  return Math.round(n * d) / d;
}

function textReplacementTask({ placeholder, correctText, width = "300px", fontFamily = "monospace", color = "black" }) {
  let enteredText = ""; 

  const root = htl.html`<div style="font-size: 14px; line-height: 1.5; margin-bottom: 20px;">
    <h4>Bitte ersetzen Sie den Text:</h4>
    <!-- Eingabefeld -->
    <div style="display: flex; align-items: center;">
      <input
        type="text"
        placeholder="${placeholder}"
        style="padding: 5px; font-size: 14px; border: 1px solid #ccc; border-radius: 4px; width: ${width}; font-family: ${fontFamily}; color: ${color};"
        onInput=${(e) => {
          enteredText = e.target.value;
          root.value = enteredText;
          root.dispatchEvent(new CustomEvent("input"));
          updateFeedback();
        }}
      />
      <!-- Feedback -->
      <div id="feedback" style="font-weight: bold; font-size: 14px; margin-left: 10px; text-align: left; white-space: nowrap; color: inherit;"></div>
    </div>
  </div>`;

// Funktion zur Aktualisierung des Feedbacks
  function updateFeedback() {
    const feedbackElement = root.querySelector("#feedback");
    if (enteredText.trim() === correctText.trim()) {
      feedbackElement.textContent = "✅";
      feedbackElement.style.color = "green";
    } else if (enteredText.trim() === "") {
      feedbackElement.textContent = ""; 
    } else {
      feedbackElement.textContent = "🔴";
      feedbackElement.style.color = "red";
    }
  }

  root.value = null; 
  return root;
}


function singleChoiceInput({ options, correctIndex }) {
  let selectedAnswer = null;

  const root = htl.html`<div style="font-size: HUGE; line-height: 1.5; margin-bottom: 0px;">
    <!-- Antworten -->
    <div style="display: grid; row-gap: 12px;">
      ${options.map(
        (option, index) =>
          htl.html`<div style="display: flex; align-items: center;">
            <!-- Radiobutton und Option -->
            <label style="display: flex; align-items: center; padding-left: 4pt; font-weight: normal;">
              <input
                type="radio"
                name="singleChoice"
                value=${index}
                style="margin-right: 10px;"
                onChange=${() => {
                  selectedAnswer = index;
                  root.value = selectedAnswer;
                  root.dispatchEvent(new CustomEvent("input"));
                  updateFeedback();
                }}
              />
              <span>${option}</span>
            </label>
            <!-- Feedback -->
            <div id="feedback-${index}" style="font-weight: bold; font-size: 14px; margin-left: 10px; text-align: left; white-space: nowrap; color: inherit;"></div>
          </div>`
      )}
    </div>
  </div>`;

// Funktion zur Aktualisierung des Feedbacks
  function updateFeedback() {
    options.forEach((_, index) => {
      const feedbackElement = root.querySelector(`#feedback-${index}`);
      if (selectedAnswer === index) {
        feedbackElement.textContent =
          index === correctIndex ? "✅" : "🔴";
        feedbackElement.style.color = index === correctIndex ? "green" : "red";
      } else {
        feedbackElement.textContent = ""; // Löscht Feedback für nicht ausgewählte Optionen
      }
    });
  }

  root.value = null;
  return root;
}


function quizInput({ questions, options}) {
  let answers = questions.map(() => null);
  let root = htl.html`<div
      style="
        display: grid;
        grid-template-columns: 10% 10% 70% 10%;"
    >
      ${options.map(
        (opt) => htl.html`<div style="font-weight: bold; font-size: HUGE">${opt}</div>`
      )}
      <div style="font-weight: bold">Statement</div>
      <div style="font-weight: bold"></div>
      ${Array.from(questions.entries(), ([i, [question, correct]]) =>
        quizInputRow({
          question,
          options,
          correct,
          onChange: (newAnswer) => {
            answers[i] = newAnswer;
            root.value = answers;
            root.dispatchEvent(new CustomEvent("input"));
          }
        })
      )}
    </div>`;
  root.value = answers;
  return root;
}

function quizInputRow({
  question,
  options,
  correct,
  onChange = () => {}
}) {
  let root = htl.html`<div>`;

  function setAnswer(answer, initial = false) {
    morph(
      root,
      htl.html`<div style="display: contents"> 
      <form style="display: contents">
        ${options.map(
          (opt) =>
            htl.html`<label>&emsp;</label> 
            <input  
              name=${question} &emsp;
              type="radio"
              value="${opt}"
              checked=${opt === answer}
              onChange=${() => setAnswer(opt)}
            >
            </input>`
        )}
      </form>
      <div>${question}</div>
      <div> &emsp; ${
       answer === null ? "" : answer === correct ? "✅" : "🔴"
      }</div>
    </div>`
    );

    root.value = answer;
    if (!initial) {
      root.dispatchEvent(new CustomEvent("input"));
      onChange(answer);
    }
  }

  setAnswer(null, true);
  return root;
}
