8 Dictionaries

Note🎯 Learning goals

After working through Tutorial 8, you’ll be able to…

  • Explain what dictionaries are and which decisions a dictionary analysis involves
  • Apply off-the-shelf dictionaries
  • Build and apply your own (organic) dictionaries

1 What are dictionaries?

So far, we have mostly described texts, for example via frequent features (Tutorial 5), co-occurrences (Tutorial 6), or syntax (Tutorial 7). Today, we want to classify text into predetermined categories: Is a TV series description negative? Is a TV series a crime series?

For this, we use dictionaries. Dictionaries are

lists of features that describe a construct (e.g., emotionality).

The idea is simple: We count how often manifest features (e.g., “bad”, “worse”) occur in a text to infer whether a latent construct (e.g., a “negative evaluation”) is present. Dictionaries are a deductive approach: We classify texts into categories that we define before the analysis.

A classic example is sentiment analysis, which rests on

“the idea that the affective content of text […] reveals information about the underlying opinions, stances, and attitudes” (Rauh, 2018, p. 320).

Dictionary analyses typically follow four steps. Each step involves decisions:

Step Important questions
1 Preprocessing Should I remove stopwords (e.g., negations such as “not”)? Should I use stemming?
2 Choosing or building a dictionary Do I use an existing off-the-shelf dictionary or build my own organic one?
3 Analysis Do I look at whole texts or only at features related to a specific object? How do I deal with negation and different text lengths? When is a construct present (threshold)?
4 Validation Does the dictionary measure what it should?

In this tutorial, we focus on the first three steps. We only need quanteda and the tidyverse, which you already installed:

# load packages (every time you restart R)
library(tidyverse)
library(quanteda)

We read in our TV series data and preprocess the descriptions as in Tutorial 3 - with two exceptions: We do not remove stopwords and we do not use stemming.

# read in the data
data <- read.csv2("data/data_tvseries.csv", encoding = "UTF-8")

# preprocessing (without stemming & without removing stopwords)
tokens_tv <- data |>
  corpus(text_field = "Description") |>
  tokens(remove_punct = TRUE,
         remove_numbers = TRUE,
         remove_symbols = TRUE) |>
  tokens_tolower()
WarningWhy do we keep stopwords and skip stemming today?

Stopwords: Lists of stopwords often include negations such as “not”. If we remove them, “that is not bad” becomes “bad” - and a dictionary would classify the text as negative.

Stemming: Many dictionaries already use wildcards: abandon* matches “abandon”, “abandoned”, and “abandonment”. If we stem our texts, features such as “famili” may no longer match the dictionary.

Again, preprocessing decisions depend on your goal (see Tutorial 6).

2 Off-the-shelf dictionaries

2.1 What are off-the-shelf dictionaries?

Off-the-shelf dictionaries are existing word lists, often developed for other contexts. Here are some examples:

Dictionary Measures
General Inquirer (GI) many categories, incl. positive & negative
Linguistic Inquiry and Word Count (LIWC) psychological & emotional categories
Lexicoder Sentiment Dictionary (LSD) sentiment in (political) news
WordNet-Affect (WNA) emotions
Bing positive & negative sentiment
AFINN sentiment scores from -5 to +5
NRC Word-Emotion Association Lexicon eight emotions & sentiment
SentimentWortschatz (SentiWS) sentiment in German texts

Off-the-shelf dictionaries have advantages: There is a large selection of existing dictionaries, so they are cheap to use. Many are already implemented in packages like quanteda. And they are transparent, i.e., no “black-box” method.

But they also have disadvantages: They are often atheoretical and of limited validity, since they were not developed for our theories and data. Boukes et al. (2020) show that off-the-shelf sentiment tools barely agree with manual coding - and barely agree with each other (see the required reading).

2.2 An Example: The Lexicoder Sentiment Dictionary

We use the Lexicoder Sentiment Dictionary (Young & Soroka, 2012), which comes with quanteda as data_dictionary_LSD2015. A dictionary consists of keys (categories) and the features belonging to each key. With [1:2], we only keep the first two keys, negative and positive:

data_dictionary_LSD2015[1:2]
Dictionary object with 2 key entries.
- [negative]:
  - a lie, abandon*, abas*, abattoir*, abdicat*, aberra*, abhor*, abject*, abnormal*, abolish*, abominab*, abominat*, abrasiv*, absent*, abstrus*, absurd*, abus*, accident*, accost*, accursed* [ ... and 2,838 more ]
- [positive]:
  - ability*, abound*, absolv*, absorbent*, absorption*, abundanc*, abundant*, acced*, accentuat*, accept*, accessib*, acclaim*, acclamation*, accolad*, accommodat*, accomplish*, accord, accordan*, accorded*, accords [ ... and 1,689 more ]

The asterisk * is a wildcard: abandon* matches every feature that starts with “abandon”.

2.3 Looking up dictionary features

To look up dictionary features, we need two functions:

  • dfm_weight(): With scheme = "prop", we calculate the share of each feature among all features of a text. This way, we account for text length: Longer texts are more likely to contain, e.g., negative features “by chance”.
  • dfm_lookup(): counts features from the dictionary per key.
sentiment_tv <- tokens_tv |>
  dfm() |>
  dfm_weight(scheme = "prop") |>
  dfm_lookup(dictionary = data_dictionary_LSD2015[1:2])

sentiment_tv

2.4 Classifying texts

Next, we classify each series as negative, neutral, or positive - depending on which features dominate. We convert the document-feature matrix into a data frame with convert(), add the original data with bind_cols(), and classify the series with case_when():

sentiment_tv <- sentiment_tv |>
  convert(to = "data.frame") |>
  bind_cols(data) |>
  mutate(sentiment = case_when(
    positive > negative ~ "positive",
    negative > positive ~ "negative",
    .default = "neutral"))

sentiment_tv |>
  select(Title, positive, negative, sentiment) |>
  head(4)
               Title   positive  negative sentiment

2    2. Breaking Bad 0.04000000 0.0400000   neutral
3 3. Stranger Things 0.04545455 0.1363636  negative
4         4. Friends 0.04545455 0.0000000  positive

WarningDo dictionaries make mistakes?

Yes - a lot! Dictionaries ignore context. Let’s look at the description of “Dexter”:

sentiment_tv |>
  filter(Title == "8. Dexter") |>
  select(Description, positive, negative, sentiment)
                                                                                                                                     Description
1 He's smart. He's lovable. He's Dexter Morgan, America's favorite serial killer, who spends his days solving crimes and nights committing them.
   positive  negative sentiment
1 0.1904762 0.0952381  positive

The description of a series about a serial killer is classified as positive. Why? “smart”, “lovable”, and “favorite” are positive - and so is “Dexter” itself, since the dictionary contains dexter* (as in “dexterous”). This is a typical problem of polysemy, i.e., features with several meanings.

Dictionaries also struggle with sarcasm, irony, and negation: “Not a great way to start the day” contains the positive feature “great”. Always check your results qualitatively!

3 Organic dictionaries

3.1 What are organic dictionaries?

Organic dictionaries are your own, domain-specific word lists, developed for your research question and data. Building them typically involves four steps (Muddiman et al., 2019):

  1. Identify features based on existing studies
  2. Extend them based on the corpus, e.g., by inspecting top features (Tutorial 5) or keywords-in-context (Tutorial 6)
  3. Validate each single feature
  4. Validate the whole dictionary

Organic dictionaries are often more closely tied to theoretical concepts - and thus more valid. Like off-the-shelf dictionaries, they are transparent. However, they are very time-consuming to build and hardly generalizable, since they are closely tied to one corpus.

3.2 Creating a dictionary

Which TV series are crime series? We create our own dictionary with dictionary(). It takes a list with one key (here: crime) and a vector of features:

dict_crime <- dictionary(list(
  crime = c("crim*", "police*", "gun*", "shot*", "dead*",
            "murder*", "kill*", "court*", "suspect*",
            "witness*", "arrest*", "officer*", "verdict*")))

dict_crime
Dictionary object with 1 key entry.
- [crime]:
  - crim*, police*, gun*, shot*, dead*, murder*, kill*, court*, suspect*, witness*, arrest*, officer*, verdict*

Again, the wildcard * matches any ending: crim* matches “crime”, “crimes”, “criminal”, etc.

TipCan a dictionary have more than one key?

Yes! Simply add further elements to the list, e.g., one key for crime series and one for science fiction series:

dict_genres <- dictionary(list(
  crime = c("crim*", "police*", "murder*", "detective*"),
  scifi = c("galax*", "space*", "alien*", "planet*")))

3.3 Applying the dictionary

We apply our dictionary just like the Lexicoder Sentiment Dictionary. A series counts as a crime series if it contains at least one crime feature:

crime_tv <- tokens_tv |>
  dfm() |>
  dfm_weight(scheme = "prop") |>
  dfm_lookup(dictionary = dict_crime) |>
  convert(to = "data.frame") |>
  bind_cols(data) |>
  mutate(crime_binary = if_else(crime > 0, "crime", "non-crime"))

How many crime series are there?

crime_tv |>
  count(crime_binary) |>
  mutate(share = round(n / sum(n) * 100, 1))
  crime_binary   n share
1        crime 170  18.9
2    non-crime 730  81.1

About one in five series is classified as a crime series. And which are the “clearest” crime series, i.e., the series with the highest share of crime features?

WarningWhich features does our dictionary actually find?

Wildcards are handy - but they can also match features we did not have in mind. With kwic() (Tutorial 6), we can check in which contexts our dictionary features occur. For example, for all features that start with “court”:

kwic(tokens_tv, pattern = "court*", window = 3)
Keyword-in-context with 8 matches.

 [text302, 15] on the basketball |   court   | and in the     
 [text314, 19]  trial in federal |   court   | for the murder

“The royal court of Camelot”, “on the basketball court”, or even “courtship” have nothing to do with crime. Similarly, dead* matches “The Walking Dead” and “Deadwood”. This is why we should validate each single feature (step 3 of building organic dictionaries).

3.4 Does the threshold matter?

So far, one crime feature was enough to classify a series as a crime series. But we could also be stricter. What happens if we require at least 2 or 3 crime features?

For this, we need the number of crime features, not their share - so we skip dfm_weight():

crime_counts <- tokens_tv |>
  dfm() |>
  dfm_lookup(dictionary = dict_crime) |>
  convert(to = "data.frame")

crime_counts |>
  summarise(at_least_1 = round(mean(crime >= 1) * 100, 1),
            at_least_2 = round(mean(crime >= 2) * 100, 1),
            at_least_3 = round(mean(crime >= 3) * 100, 1))
  at_least_1 at_least_2 at_least_3
1       18.9        4.6        0.8

The threshold matters a lot: Depending on our decision, 18.9%, 4.6%, or only 0.8% of all series are crime series. There is no “correct” threshold - but you should justify your decision and test whether your results change.

💡 Take-Aways

  • dictionaries: lists of features that describe a latent construct (e.g., sentiment)
  • four steps: preprocessing, choosing or building a dictionary, analysis, validation
  • off-the-shelf dictionaries: existing word lists, e.g., the Lexicoder Sentiment Dictionary: data_dictionary_LSD2015
  • organic dictionaries: your own, domain-specific word lists: dictionary()
  • looking up features: dfm_weight() (to account for text length), dfm_lookup()
  • thresholds: when a construct counts as present - this decision can change your results

🤓 Smart Hacks

TipSmart Hack 1: Negation in the Lexicoder Sentiment Dictionary

The Lexicoder Sentiment Dictionary has two more keys: neg_positive (negated positive features, e.g., “not good”) and neg_negative (negated negative features, e.g., “not bad”):

data_dictionary_LSD2015[3:4]
Dictionary object with 2 key entries.
- [neg_positive]:
  - best not, better not, no damag*, no no, not ability*, not able, not abound*, not absolv*, not absorbent*, not absorption*, not abundanc*, not abundant*, not acced*, not accentuat*, not accept*, not accessib*, not acclaim*, not acclamation*, not accolad*, not accommodat* [ ... and 1,701 more ]
- [neg_negative]:
  - not a lie, not abandon*, not abas*, not abattoir*, not abdicat*, not aberra*, not abhor*, not abject*, not abnormal*, not abolish*, not abominab*, not abominat*, not abrasiv*, not absent*, not abstrus*, not absurd*, not abus*, not accident*, not accost*, not accursed* [ ... and 2,840 more ]

These are multi-word features, which dfm_lookup() cannot find (a document-feature matrix only contains single features). Instead, we use tokens_lookup() on our tokens. With nested_scope = "dictionary", “not good” is only counted as neg_positive - and not additionally as positive:

toy <- tokens(c("This series is not good", "This series is not bad")) |>
  tokens_tolower()

# only negative & positive: "not good" is positive, "not bad" negative
toy |>
  tokens_lookup(dictionary = data_dictionary_LSD2015[1:2]) |>
  dfm()
Document-feature matrix of: 2 documents, 2 features (50.00% sparse) and 0 docvars.
       features
docs    negative positive
  text1        0        1
  text2        1        0
# all four keys: correct
toy |>
  tokens_lookup(dictionary = data_dictionary_LSD2015,
                nested_scope = "dictionary") |>
  dfm()
Document-feature matrix of: 2 documents, 4 features (75.00% sparse) and 0 docvars.
       features
docs    negative positive neg_positive neg_negative
  text1        0        0            1            0
  text2        0        0            0            1

To classify texts, you can then add negated features to the opposite category, e.g., negative = negative + neg_positive and positive = positive + neg_negative.

function textReplacementWithText({ text, placeholder, correctText, fontFamily = "monospace", color = "#000000" }) {
  const parts = text.split(/\{\{input\}\}/); // Teilt den Text an den Eingabestellen

  const root = htl.html`<div style="font-size: HUGE; margin-top: -40; margin-bottom: -40; margin-left: -50px; line-height: 1.8; font-family: ${fontFamily}; color: ${color}; white-space: pre-wrap; text-indent: 0; display: flex; align-items: baseline;">
    <div style="flex: 1;">
      ${parts.map((part, index) =>
        htl.html`${part}${index < parts.length - 1 ? htl.html`<span style="display: inline-flex; align-items: baseline;">
          <input 
            type="text"
            placeholder="${placeholder}"
            style="padding: 3px; font-size: HUGE; border: 1px solid #ccc; margin-left: 0px; border-radius: 4px; width: calc(${correctText.length}ch + 1em); font-family: ${fontFamily}; color: ${color}; text-align: right; box-sizing: border-box; margin-right: 0.2em;"
            oninput=${(e) => {
              const feedbackElement = root.querySelector(`#feedback-final`);
              const allInputsCorrect = Array.from(root.querySelectorAll("input")).every((input) => input.value.trim() === correctText.trim());
              if (allInputsCorrect) {
                feedbackElement.textContent = "✅";
                feedbackElement.style.color = "green";
              } else {
                feedbackElement.textContent = "🔴";
                feedbackElement.style.color = "red";
              }
            }}
          /></span>` : ""}`
      )}
    </div>
    <span id="feedback-final" style="font-weight: bold; font-size: HUGE; margin-left: 0.5em; color: inherit;"></span>
  </div>`;

  return root;
}

  let enteredText = "";

        }}

// Funktion zur Aktualisierung des Feedbacks
  function updateFeedback() {

    if (enteredText.trim() === correctText.trim()) {

function singleChoiceInput({ options, correctIndex }) {
  let selectedAnswer = null;

  const root = htl.html`<div style="font-size: HUGE; line-height: 1.5; margin-bottom: 0px;">
    <!-- Antworten -->
    <div style="display: grid; row-gap: 12px;">
      ${options.map(
        (option, index) =>
          htl.html`<div style="display: flex; align-items: center;">
            <!-- Radiobutton und Option -->
            <label style="display: flex; align-items: center; padding-left: 4pt; font-weight: normal;">
              <input
                type="radio"
                name="singleChoice"
                value=${index}
                style="margin-right: 10px;"
                onChange=${() => {
                  selectedAnswer = index;
                  root.value = selectedAnswer;
                  root.dispatchEvent(new CustomEvent("input"));
                  updateFeedback();
                }}
              />
              <span>${option}</span>
            </label>
            <!-- Feedback -->
            <div id="feedback-${index}" style="font-weight: bold; font-size: 14px; margin-left: 10px; text-align: left; white-space: nowrap; color: inherit;"></div>
          </div>`
      )}
    </div>
  </div>`;

// Funktion zur Aktualisierung des Feedbacks
  function updateFeedback() {
    options.forEach((_, index) => {
      const feedbackElement = root.querySelector(`#feedback-${index}`);
      if (selectedAnswer === index) {
        feedbackElement.textContent =
          index === correctIndex ? "✅" : "🔴";
        feedbackElement.style.color = index === correctIndex ? "green" : "red";
      } else {
        feedbackElement.textContent = ""; // Löscht Feedback für nicht ausgewählte Optionen
      }
    });
  }

  root.value = null;
  return root;
}


function quizInput({ questions, options}) {
  let answers = questions.map(() => null);
  let root = htl.html`<div
      style="
        display: grid;
        grid-template-columns: 10% 10% 70% 10%;"
    >
      ${options.map(
        (opt) => htl.html`<div style="font-weight: bold; font-size: HUGE">${opt}</div>`
      )}
      <div style="font-weight: bold">Statement</div>
      <div style="font-weight: bold"></div>
      ${Array.from(questions.entries(), ([i, [question, correct]]) =>
        quizInputRow({
          question,
          options,
          correct,
          onChange: (newAnswer) => {
            answers[i] = newAnswer;
            root.value = answers;
            root.dispatchEvent(new CustomEvent("input"));
          }
        })
      )}
    </div>`;
  root.value = answers;
  return root;
}

function quizInputRow({
  question,
  options,
  correct,
  onChange = () => {}
}) {
  let root = htl.html`<div>`;

  function setAnswer(answer, initial = false) {
    morph(
      root,
      htl.html`<div style="display: contents"> 
      <form style="display: contents">
        ${options.map(
          (opt) =>
            htl.html`<label>&emsp;</label> 
            <input  
              name=${question} &emsp;
              type="radio"
              value="${opt}"
              checked=${opt === answer}
              onChange=${() => setAnswer(opt)}
            >
            </input>`
        )}
      </form>
      <div>${question}</div>
      <div> &emsp; ${
       answer === null ? "" : answer === correct ? "✅" : "🔴"
      }</div>
    </div>`
    );

    root.value = answer;
    if (!initial) {
      root.dispatchEvent(new CustomEvent("input"));
      onChange(answer);
    }
  }

  setAnswer(null, true);
  return root;
}
